# Data

Synthetic data fixtures, policy samples, and seed inputs used for development and demonstration.

Keep all data synthetic and do not add real customer or personal information.

## Synthetic receivables fixture

`demo/receivables.json` is generated by
`backend/scripts/generate_synthetic_data.py`. The canonical fixture uses seed
`2026` and reference date `2026-12-15`.

Regenerate it from the repository root with:

```bash
python backend/scripts/generate_synthetic_data.py
```

The seed, reference date, tenant ID, and output path are configurable with
`--seed`, `--reference-date`, `--tenant-id`, and `--output`.

The fixture contains 120 synthetic customers, 1,500 invoices, 2,500 payments,
and 30 promises. It is demo data, not measured or real-world evidence.
The invoice dates cover a rolling 365-day period. Monthly weights create
an illustrative seasonal pattern for demonstration only; they are not
based on real market statistics.

`demo/receivables_import_sample.csv` is a separate, intentionally messy
sample for import-validation testing. It includes duplicate invoice numbers,
missing contact fields, and inconsistent date and amount formats.
It is not part of the canonical JSON fixture.
